# Разработка веб-приложения для системы управления космическим флотом

В данном разделе рассматривается процесс проектирования и реализации веб-приложения для управления космическим флотом. Система предназначена для мониторинга состояния космических кораблей, управления экипажем, планирования миссий и проведения научных экспериментов.

## 1. Выбор технологий и обоснование стека

Для реализации системы был выбран современный стек технологий, обеспечивающий высокую производительность, масштабируемость и удобство разработки.

### Серверная часть (Backend):
- **Java 21**: Последняя версия языка с долгосрочной поддержкой (LTS), предоставляющая современные возможности, такие как виртуальные потоки и улучшенный синтаксис.
- **Spring Boot 4.0**: Фреймворк для быстрого создания готовых к работе приложений. Использование Spring Boot позволяет минимизировать конфигурацию и сосредоточиться на бизнес-логике.
- **Spring JDBC (JdbcTemplate)**: Выбран вместо высокоуровневых ORM (таких как Hibernate) для обеспечения полного контроля над SQL-запросами и оптимизации производительности взаимодействия с базой данных. Это позволяет писать «чистый» SQL, что критично для сложных выборок и аналитики.
- **PostgreSQL**: Реляционная база данных, известная своей надежностью, поддержкой сложных типов данных и соответствием стандартам ACID.
- **Liquibase**: Инструмент для управления миграциями базы данных. Обеспечивает версионность схемы БД и воспроизводимость структуры на разных окружениях.
- **Spring Security**: Для обеспечения безопасности приложения, управления аутентификацией и авторизацией.
- **SpringDoc OpenAPI (Swagger)**: Для автоматической генерации интерактивной документации API, что упрощает интеграцию с фронтендом.
- **Lombok**: Библиотека для сокращения шаблонного кода (boilerplate) в Java-классах.

### Клиентская часть (Frontend):
- **Next.js 16 + React 19**: Современный фреймворк для создания быстрых и SEO-оптимизированных веб-интерфейсов.
- **TypeScript**: Строгая типизация позволяет избежать множества ошибок на этапе разработки и упрощает рефакторинг.
- **Tailwind CSS + shadcn/ui**: Инструментарий для создания адаптивного и эстетичного интерфейса с использованием готовых, но гибко настраиваемых компонентов.

## 2. Реализация серверной части (Backend)

Серверная часть приложения построена по классической многослойной архитектуре, что обеспечивает четкое разделение ответственности и легкость тестирования.

### Архитектурные слои:
1.  **Контроллеры (Controllers)**: Обрабатывают входящие HTTP-запросы, валидируют входные данные и делегируют выполнение бизнес-логики сервисном слою.
2.  **Сервисы (Services)**: Содержат основную бизнес-логику приложения. Они координируют работу с различными DAO и выполняют преобразования данных.
3.  **Слой доступа к данным (DAO)**: Реализован с использованием `JdbcTemplate`. Включает в себя SQL-запросы для выполнения CRUD-операций и сложных выборок.
4.  **Модели данных и DTO**:
    - **Models**: Отражают структуру таблиц базы данных.
    - **DTO (Data Transfer Objects)**: Используются для передачи данных между клиентом и сервером, скрывая внутреннюю структуру БД и предотвращая избыточность данных.
    - **Mappers**: Отвечают за преобразование моделей в DTO и обратно.

### Ключевые особенности реализации:
- **Управление транзакциями**: Для обеспечения целостности данных при выполнении связанных операций (например, создание миссии и назначение экипажа) используется декларативное управление транзакциями Spring (`@Transactional`).
- **Валидация данных**: Входные данные проверяются как на уровне контроллеров (Bean Validation), так и внутри бизнес-логики.
- **Обработка исключений**: Реализован глобальный обработчик исключений (`GlobalExceptionHandler`), который перехватывает ошибки и возвращает клиенту понятные сообщения в формате JSON.
- **Миграции БД**: Все изменения структуры базы данных описаны в XML/YAML файлах Liquibase, что позволяет автоматически обновлять схему БД при запуске приложения.

#### Детализация работы с базой данных:
- **JdbcTemplate**: Ядро слоя доступа к данным. `JdbcTemplate` используется для выполнения SQL-запросов напрямую, что обеспечивает максимальную гибкость и контроль над взаимодействием с БД. Это позволяет писать оптимизированные запросы и избегать "магии" ORM, которая иногда скрывает неэффективные операции.
- **RowMapper**: Для преобразования результатов запросов (`ResultSet`) в объекты Java-моделей используется `RowMapper`. Это позволяет четко определить, как данные из каждой строки таблицы мапятся на поля соответствующего Java-объекта, обеспечивая типобезопасность и предсказуемость.
- **SimpleJdbcInsert**: Для операций вставки, особенно когда необходимо получить автоматически сгенерированный базой данных ID, применяется `SimpleJdbcInsert`. Этот компонент упрощает процесс вставки, автоматически определяя метаданные таблицы и позволяя легко возвращать сгенерированные ключи.
- **Прямые SQL-запросы**: Все DAO-методы используют прямые SQL-запросы для выполнения операций CRUD (Create, Read, Update, Delete) и более сложных выборок. Этот подход позволяет полностью контролировать логику запросов, оптимизировать их под конкретные сценарии и использовать специфические возможности PostgreSQL (например, `ILIKE` для регистронезависимого поиска, как показано в `SpacecraftDaoImpl`).

### Интеграция и API:
Backend предоставляет RESTful API, защищенное базовой аутентификацией. Все эндпоинты задокументированы с помощью Swagger UI, доступного по адресу `/swagger-ui.html`, что позволяет тестировать API без использования сторонних инструментов.
